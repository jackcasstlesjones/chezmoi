# Bugs found reviewing `refactor/tidy-up` against `main` (2026-11-05)

Nothing here is fixed yet.

## Most likely to cause problems

### 1. Changing theme can undo monitor changes

`dot_config/waybar/scripts/executable_wallpaper-theme.sh` ends with `hyprctl reload`, which should reapply the `hl.monitor` rules in `config/monitors.lua`. Runtime changes made with `hyprctl eval` would be lost:

- The laptop panel would turn back on with the lid closed (`lid.sh`).
- The Samsung resolution set with Super+R (`toggle-samsung-res.sh`) would reset.

**Status:** inferred from reading the code. A reload wasn't run on the live session.

**Suggested fix:** replace the reload with a `hyprctl eval` that only updates the border colours, so monitor state is left alone. This syntax hasn't been tested yet.

### 2. Reload may leave config stale

The split config relies on `require`, and Lua normally caches modules in `package.loaded`. If Hyprland keeps its Lua state across `hyprctl reload`, `config.colors` and the modules that register binds and rules might not run again, so colours or binds might not refresh.

**Status:** unverified. Borders currently match pywal's `color11`, but that doesn't prove a reload refreshes them.

**To check:** switch to a theme with a different `color11` and see whether the borders change, then confirm the binds still work. The fix suggested in #1 would also stop theme switches depending on this.

## Confirmed, smaller problems

### 3. Dead hyprpaper command

`hyprctl hyprpaper preload` in `executable_wallpaper-theme.sh` returns `error: invalid hyprpaper request` on hyprpaper 0.8.4. It doesn't stop the script.

The `hyprctl hyprpaper wallpaper` line after it wasn't tested, because that would change the wallpaper.

**Suggested fix:** remove the `preload` line.

### 4. Cava won't work if re-enabled

`.chezmoiignore` excludes `.config/scripts/waybar-cava.sh`, so it never gets deployed, and it's missing from `~/.config/scripts/`. `modules/waybar-cava.jsonc` points to that path. The module is commented out for now, so nothing is broken until it's turned back on.

**Suggested fix:** remove the ignore line when re-enabling cava.

### 5. `.luarc.json` isn't deployed

chezmoi skips dot-prefixed source files, so `dot_config/hypr/.luarc.json` never reaches `~/.config/hypr/`. The Lua stubs only work when editing from the chezmoi source directory.

**Suggested fix:** if the stubs are needed in `~/.config/hypr`, add a `dot_luarc.json` alongside the existing file. Renaming would deploy it but stop the stubs working in the source directory.

## Only matters on a fresh install

### 6. Missing wallpaper

`flower-dark.jpg` is in the `executable_wallpaper-theme.sh` picker and in `~/.config/wallpapers/`, but not in `dot_config/wallpapers/`.

**Suggested fix:** add it to the repo or remove it from the picker.

### 7. Waybar colours depend on pywal's cache

`dot_config/waybar/style.css` now gets all its colours from `/home/jack/.cache/wal/colors-waybar.css`, and nothing in the repo generates that file on a new install. The bar would probably come up with broken colours until `wal` first runs.

**Status:** inferred from reading the code. Not tested on a clean install.

**Suggested fix:** add a chezmoi `run_once_` script that runs `wal` with a default theme.
