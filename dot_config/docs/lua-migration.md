# Hyprland hyprlang → Lua migration record

**Date:** 2026-09-10 · **Hyprland:** 0.56.2 · **Status:** ported and deployed, **not yet live**

Companion to `hyprland-lua.md` (the general syntax reference). This file records
what was actually done to *this* machine's config, why, and what still needs
checking.

---

## 1. Outcome

| | |
| --- | --- |
| Created | `dot_config/hypr/hyprland.lua` (462 lines) |
| Deployed to | `~/.config/hypr/hyprland.lua` via `chezmoi apply` |
| Left untouched | `dot_config/hypr/hyprland.conf` (rollback path) |
| Live config manager | **still hyprlang** — needs a full restart to switch |

`hyprctl reload` does *not* switch formats. It re-reads whichever format was
selected at compositor startup and returns `ok` regardless, which is misleading.

## 2. Source of truth

The migration guide in `hyprland-lua.md` was written against v0.55.4 and warns
its tables may drift. This port was instead checked against what 0.56.2 actually
ships:

- **`/usr/share/hypr/stubs/hl.meta.lua`** — 67 KB autogenerated LuaLS stub with
  the complete `hl.*` surface, every valid `HL.ConfigKey`, and the field lists
  for `HL.BindOptions`, `HL.DeviceSpec`, `HL.MonitorSpec`, `HL.Window`, etc.
  This is the authoritative reference; consult it before the wiki.
- **`/usr/share/hypr/hyprland.lua`** — the official example config, useful for
  idiom (e.g. it passes `{ mouse = true }` to `hl.bind` even though that key is
  absent from the `HL.BindOptions` stub class).

Two discrepancies with `hyprland-lua.md` worth knowing:

- `hl.permission` is documented in the stub as taking a spec table
  (`{ binary, type, mode }`), but the shipped example uses three positional
  args. Ours stays commented out, so it was not resolved.
- `HL.BindOptions` in the stub has no `mouse` field, yet the example config uses
  it for `bindm`. Kept the example's form.

## 3. Translation decisions

Straightforward mappings (`section { }` → `hl.config`, `bind =` → `hl.bind`,
`windowrule` → `hl.window_rule`, …) are covered in `hyprland-lua.md`. Only the
non-obvious calls are recorded here.

### 3.1 pywal colors

`hyprland.conf` did `source = ~/.cache/wal/colors-hyprland.conf` and referenced
`$color11` / `$color8` / `$background`. Lua's `require` cannot load a hyprlang
file, so `hyprland.lua` opens and parses it directly:

```lua
local function load_wal_colors()
    local defaults = { foreground = "...", background = "...", color8 = "...", color11 = "..." }
    local colors = {}
    local f = io.open(os.getenv("HOME") .. "/.cache/wal/colors-hyprland.conf", "r")
    if f then
        for line in f:lines() do
            local name, value = line:match("^%s*%$([%w_]+)%s*=%s*(%S+)")
            if name then colors[name] = value end
        end
        f:close()
    end
    return setmetatable(colors, { __index = defaults })
end
```

The metatable fallback carries the current Nord values, so a missing or
half-written cache file degrades to sane borders instead of erroring the config.
Colors are read at config load, same as `source` was — `wal -R` still needs a
reload to take effect.

### 3.2 Shell-outs converted to native Lua

Two binds shelled out to `hyprctl` to do things the Lua API can now do directly.
Converting them removes a dependency on legacy `hyprctl` syntax (see §5).

| Bind | Was | Now |
| --- | --- | --- |
| `SUPER+SHIFT+Q` | `hyprctl clients -j \| jq … \| xargs hyprctl dispatch closewindow` | `hl.get_workspace_windows()` loop over `hl.dsp.focus` + `hl.dsp.window.close()` |
| `hyperkey+P` | `hyprctl activewindow -j \| jq … \| hyprctl --batch` | `hl.get_active_window().pinned` branch over `window.pin`/`window.float` |
| `exec-once = hyprctl dispatch workspace name:N` | shell | `hl.dispatch(hl.dsp.focus({ workspace = "name:N" }))` |

Commands that only *query* (`hyprctl clients -j`, `hyprctl activewindow -j` in
the calculator and Chrome-Ctrl+T binds) were left as shell — queries are not
format-sensitive.

### 3.3 Odd constructs

- **`bind` nested inside `input:touchpad`** — `bind = , mouse:274, exec,` (an
  empty exec, i.e. swallow middle-click) became a top-level
  `hl.bind("mouse:274", hl.dsp.no_op())`.
- **`device { bindel = … }`** — the SK75 keyboard's F11/F12 volume binds became
  ordinary binds with `device = { inclusive = true, list = { "telink-wireless-gaming-keyboard" } }`.
- **Switch binds** — `switch:off:Lid Switch` is passed through verbatim as the
  key string; it survives `hl.bind` unchanged.
- **`animations { enabled = yes, please :) }`** → `enabled = true`.
- **`animation = workspaces, 0, …`** — the leading `0` is the enabled flag, so
  these became `enabled = false` (not speed 0).
- **`exec-once = [workspace name:N silent] kitty …`** → `hl.exec_cmd(cmd, { workspace = "name:N silent" })`.
- Repeated `windowrule` lines sharing a match (calculator, pavucontrol, bluetui,
  yazi-float, ulauncher) were collapsed into one `hl.window_rule` call each:
  24 hyprlang lines → 12 Lua calls.

### 3.4 Two binds deliberately dropped

`hyprctl binds` confirmed both of these were registered but **dead** — Hyprland
runs the first matching bind and consumes the key:

| Key | Dead bind | Winner |
| --- | --- | --- |
| `SUPER+B` | `exec wtype n` | `exec kitty … bluetui` |
| `hyperkey+N` | `workspace name:N` | `exec scratchpad.sh` |

Rather than reproduce dead weight — and because it is unverified whether
`hl.bind` on a duplicate key *appends* (hyprlang behaviour) or *replaces* (which
would silently flip which one wins) — both were removed and commented in place.
`hyperkey+R` remains the working way to reach workspace N.

## 4. Verification method

Reproducible. From `dot_config/hypr/`:

**Syntax:**

```sh
luac -p hyprland.lua
```

**Behavioural parity** — run the config against a mock `hl` that records every
`hl.bind`, normalise to `modmask key`, and diff against the live hyprlang binds:

```sh
hyprctl binds -j | jq -r '.[] | "\(.modmask) \(.key)"' | sort > /tmp/live-binds.txt
# harness stubs hl.* and hl.dsp.* namespaces, then dofile("hyprland.lua")
lua harness.lua | sort > /tmp/lua-binds.txt
diff <(tr 'A-Z' 'a-z' < /tmp/live-binds.txt | sort -u) \
     <(tr 'A-Z' 'a-z' < /tmp/lua-binds.txt  | sort -u)
```

modmask bits: `SHIFT=1 CAPS=2 CTRL=4 ALT=8 SUPER=64`. The hyperkey
(`CTRL_SHIFT_ALT_SUPER`) is **77**.

**Results:**

- Key-combo set: **identical**, no missing binds, no extras.
- Per-combo counts: differ only at `64 b` and `77 n` — the two dead binds in §3.4.
- Call tally matched the source config exactly: 4 monitors, 4 env, 3 devices,
  6 curves, 16 animations, 12 window rules, 1 workspace rule, 111 binds.
- Every `hl.config` key cross-checked against the stub's `HL.ConfigKey` list
  (`misc.on_focus_under_fullscreen`, `dwindle.force_split`,
  `xwayland.force_zero_scaling`, `decoration.dim_inactive`, … all valid).
- pywal loader tested standalone: resolves `color11`/`color8`/`background`
  correctly and returns `nil` for absent keys.

## 5. Open risk: `hyprctl` in external scripts

**This is the thing most likely to break, and it is unresolved.**

`hyprctl` behaves differently per config format. Measured under the *current*
hyprlang config:

| Command | Result |
| --- | --- |
| `hyprctl dispatch exec true` (legacy) | `ok` |
| `hyprctl dispatch 'hl.dsp.no_op()'` (Lua form) | `Invalid dispatcher` |
| `hyprctl eval` / `hyprctl repl` | `eval is only supported with the lua config manager` |

So the Lua form is rejected under hyprlang. Whether the **legacy form is
rejected under Lua** could not be determined without switching. The shipped
example config uses `hyprctl dispatch 'hl.dsp.exit()'`, which hints the Lua form
is expected there — if legacy names are gone, the scripts below break.

`hyprctl keyword` is the bigger worry: it is a hyprlang concept with no obvious
Lua-mode equivalent short of `hyprctl eval 'hl.monitor({...})'`.

**Files to test immediately after switching:**

| File | Uses | Impact if broken |
| --- | --- | --- |
| `scripts/executable_lid.sh` | `hyprctl keyword monitor` | **clamshell mode dead** |
| `scripts/executable_toggle-samsung-res.sh` | `hyprctl keyword monitor` | resolution toggle dead |
| `hypr/scripts/scratchpad.sh` | `dispatch focuswindow/sendshortcut/exec` | hyperkey+N scratchpad |
| `hypr/scripts/executable_move-to-workspace.sh` | `dispatch movetoworkspace` | SUPER+SHIFT+O |
| `hypr/scripts/executable_workspace-switcher.sh` | `dispatch workspace` | — |
| `scripts/executable_toggle-workspaces-monitors.sh` | `dispatch moveworkspacetomonitor` | hyperkey+period |
| `scripts/executable_system-menu.sh` | `dispatch exit` | SUPER+M logout |
| `wlogout/layout` | `dispatch exit` | wlogout logout button |
| `hypr/hypridle.conf.tmpl` | `dispatch dpms on` | **screen stays black after sleep** |

## 6. Switching over and rolling back

Format selection happens **once at compositor startup**. Either:

```sh
# clean: log out and back in
# or, live (wiki: "don't use unless really necessary"):
hyprctl reload full-reset
```

Then immediately:

```sh
hyprctl configerrors      # should be empty
hyprctl eval 'return hl.version()'   # proves the Lua manager is active
```

**Rollback** — from a TTY (`Ctrl+Alt+F3`):

```sh
mv ~/.config/hypr/hyprland.lua ~/.config/hypr/hyprland.lua.wip
# restart Hyprland → hyprland.conf takes over again
```

Note `chezmoi apply` will re-deploy the `.lua` and put you back on the Lua path,
so hold off on running it until the config is proven. Once it is, delete
`hyprland.conf` from the chezmoi source so the two cannot drift.

## 7. Leftovers

- `hyprland.conf` and `hyprland.lua` both exist in chezmoi. Intentional for now
  (rollback); remove the `.conf` once the Lua config is confirmed good.
- Gestures were commented out in the source config and stayed commented out.
- Permissions (`ecosystem.enforce_permissions`, `hl.permission`) stayed
  commented out; if enabled later, note they need a full restart, not a reload.
- Set up the Hyprland Lua LSP against `/usr/share/hypr/stubs/hl.meta.lua` for
  autocomplete on `hl.*` and the `hl.get_*()` return types.
